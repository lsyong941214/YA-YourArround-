# apps/admin — 관리자 웹 작업 규칙

`docs/rules/RULE_00_COMMON.md`(공통 규칙)를 먼저 따른다. 일반 사용자 앱·웹뷰와 **별도 도메인·별도 배포**다.

## 스택

React · TypeScript(strict) · Vite · TanStack Query · React Hook Form · Zod · shadcn/ui · Tailwind(디자인 토큰) · pnpm · Cloudflare Workers Static Assets

## MVP 기능

| 영역 | 기능 |
|---|---|
| 회원·신고 | 회원 조회, 이용 제한·해제, 신고 대기열(접수→검토→처리→재검토), 사유·근거 기록 |
| 문의·피드백 | 목록·답변·해결 상태, 앱 버전·설정 버전·`request_id` 연결 |
| 공지·정책 | 공지·FAQ·약관 초안 → 미리보기 → 게시, 버전 이력 |
| 테스트 콘텐츠 | 문항·선택지·이미지·결과 설명, 문항 세트·계산 규칙 버전 |
| 운영 설정 | 기능별 대상·신청 한도·점검 안내·권장/최소 앱 버전, 되돌리기 (초대 만료·발급 한도, 대기열 만료, 열람 허락 기간·일일 한도 포함) |
| 온보딩 콘텐츠 | 앱 소개·역할 안내의 문구·이미지·순서, 초안→미리보기→게시 |
| 입력 목록 | 회사명 목록(직접 입력된 새 이름 검토·표기 통일·병합), 시군구 목록 갱신 |
| 이장 네트워크 | 이장 연결 현황, 과도한 열람(일일 한도 반복 도달) 이장 확인 |
| 지표 | 가입 → 프로필 완료 → 초대 연결 → 매칭 수락 → 테스트 완료 → 첫 대화·답장 |
| 감사 기록 | 작업자·시간·변경 전후·사유, 푸시 발송 실패 내역 |

## 규칙

- 로그인: Supabase Auth + **TOTP MFA 필수**. aal2가 아니면 MFA 화면으로. 운영자 여부는 서버의 `admin_roles`로 판단.
- 모든 데이터는 `/v1/admin/*` API로. 테이블 직접 조회·`service_role` 키 사용 금지.
- **모든 변경 작업은 사유 입력 필수** → 서버가 감사 기록에 저장. 사유 없는 변경 버튼을 만들지 않는다.
- 콘텐츠·설정·문항은 게시본을 덮어쓰지 않는다. 새 버전 생성 → 미리보기 → 테스트 그룹 → 게시. 되돌리기는 이전 버전 재게시.
- 진행 중 주변인 테스트는 시작 시 고정된 문항 버전을 계속 쓴다는 안내를 문항 게시 화면에 표시.
- 신고 처리: 신고 건수만으로 영구 정지를 확정하는 자동 버튼을 만들지 않는다. 판단은 운영자, 근거 필수.
- **전체 채팅 열람 화면 없음.** 신고에 첨부된 메시지(증거)와 앞뒤 제한된 범위만 보여준다. 열람도 감사 기록 대상.
- 폼은 RHF + Zod 스키마(가능하면 `packages/api-contract` 스키마에서 생성)로 검증. 서버 오류 `code`를 필드에 매핑.
- 서버 상태는 TanStack Query만. 전역 상태 라이브러리를 추가하지 않는다.
- 운영자도 초대코드의 휴대폰 번호를 볼 수 없다(저장하지 않음). 초대 문제 문의는 코드·발급 이장·시각으로만 확인한다.
- 개인정보 표시는 필요한 최소 범위(이메일 일부 마스킹 등), 목록 CSV 내보내기는 MVP 제외.

## 명령어

```bash
pnpm -F admin dev
pnpm -F admin lint && pnpm -F admin typecheck && pnpm -F admin test && pnpm -F admin build
```
