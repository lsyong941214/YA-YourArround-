# CHANGELOG

## v0.9.0 - 임시 로그인/세션 도입, 다중 유저 데이터 분리
- 로그인 세션 저장소 추가 (`src/lib/store/auth_store.ts`)
  - 실제 로그인 API 연동 전까지, 텍스트 입력으로 계정(이름/역할/담당 마을 또는 연결 주민/나이/직업/MBTI/지역/소개/프로필 사진)을 만들고 전환
  - 함수 시그니처(`curr_user`, `do_logout` 등)는 유지한 채 추후 내부 구현만 API 세션으로 교체 가능하도록 설계
- 임시 로그인 화면 신규 구현 (`/login/local`, `LocalLoginScreen.tsx`), 기존 로그인 화면의 "휴대폰 번호로 시작하기"에서 연결
- 마이페이지 신규 구현 (`/mypage`, `MyPageScreen.tsx`) - 내 프로필 확인, 로그아웃, 계정 전환
- 홈 화면의 "민지" 하드코딩을 제거하고 로그인한 유저 정보(이름/사진/소개/역할)를 사용하도록 전환, 미로그인 시 로그인 화면으로 이동
- 매칭 요청/주변인 테스트 요청에 요청자 유저 ID(`req_uid`) 추가
  - 이장님의 "진행중인 매칭"은 본인이 담당하는 마을(jang_id)의 요청만 표시
  - 주민의 "받은 제안함"은 본인과 연결된 주민 프로필(memb_id)로 온 요청만 표시
  - "내가 보낸 요청" 목록 신규 구현 (`/sent`, `SentListScreen.tsx`)로 보낸 요청들의 진행 상태 확인 가능
- 주변인 테스트 수신 화면 신규 구현 (`/blind/[blnd_id]`, `BlndReviewScreen.tsx`) - 최소한의 수락/거절 기능(밸런스 게임은 추후 구현)
- 여러 계정(주민1 → 이장2 승인 → 주민2 수락 → 주민1 확인, 주민1 주변인 테스트 → 주민2 수락)으로 실제 전환하며 전체 플로우를 검증
- SSR 하이드레이션 불일치 버그 수정: `LocalLoginScreen`/`ChiefReviews`에서 localStorage 조회를 `useEffect`로 이동
