## v0.3.6 - 주변인 테스트 신청 실패 원인 규명: blind_test_picks.card_idx 누락

## v0.3.0 - 초대코드 기반 주민-이장 연결
- **연결 생성 경로를 초대코드로 일원화** (이전까지는 연결을 만드는 UI 자체가 없었고,
  `add_cntc()`는 어디서도 호출되지 않는 죽은 코드였다)
  - 발급 방향: **이장이 발급 → 주민이 입력**. 코드를 쥐고 있다는 것 자체가 "이장이 인정한
    사람"이라는 인증이라, 코드 사용 후 별도 승인 단계는 두지 않는다
  - 코드 수명: **1회용, 만료 없음**. 한 명이 쓰면 소진(`used_by`/`used_at` 기록)
  - 코드 형식: 혼동 문자(0/O/1/I/L) 제외 8자리, 화면에는 `ABCD-2345` 형태로 끊어 표시
- **`invite_codes` 테이블 + `use_invt_code()` 함수 신설** (`supabase/alter_invt.sql`)
  - 주민은 `invite_codes`를 **조회할 수 없다**(코드 열거 방지). 코드 사용은 SECURITY DEFINER
    함수가 대신 처리하며, 코드 확인 → 연결 생성 → 코드 소진이 한 트랜잭션에서 이뤄진다
  - 동시에 같은 코드를 쓰는 경우를 막기 위해 `select ... for update`로 행을 잠근다
  - 자기 코드 사용/이미 사용된 코드/이미 연결됨 등을 상태 코드로 구분해 안내 문구를 나눈다
- **보안 구멍 제거**: `village_contacts`의 `contacts_insert_resident` 정책을 내렸다.
  이 정책은 주민이 **아무 이장에게나 동의 없이** 자신을 연결할 수 있게 허용하고 있었다.
  이제 연결은 `use_invt_code()`를 통해서만 만들어진다
- **화면 신설** `/invt` (`src/components/invt/InvtScreen.tsx`) — 역할에 따라 갈라짐
  - 이장: 코드 발급 / 복사 / 폐기, 발급 목록과 사용 여부(누가 썼는지) 표시
  - 주민: 코드 입력 → 연결. 성공 시 연결된 이장님 보기로 이어짐
  - 진입점: 홈 화면 연락처 카드, 연락처 목록 화면 상단(연결이 없을 때 막다른 길이 되지 않도록)
- `cntc_store`는 조회 전용으로 정리(`add_cntc` 제거)
